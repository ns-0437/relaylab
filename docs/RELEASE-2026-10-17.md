## Lifecycle contract

Admission reserves a slot before database insertion. One stable promise covers
insertion, execution, and cleanup, including cancellation during insertion.
The singleton tracks a monotonic deadline from before each database call,
rejects changed epochs, and cancels execution on loss. Explicit release checks
both owner and epoch. A successor's interrupted lifecycle row cannot be
overwritten by the old executor.

Shutdown blocks admission immediately. Its configurable deadline reports a
timeout honestly; that result does not prove cleanup finished. The current
executor has one lifecycle per process: restart the process after shutdown or
ownership loss. The UI list exposes a degraded terminal-write failure as
interrupted with an explanatory error; durable reconciliation still occurs
on restart.

## Remaining acceptance work

- Browser evidence remains manual screenshots and interaction; no checked-in
  automated browser acceptance suite is included.
- Live Anthropic execution remains unverified. It requires explicit opt-in.
- Verification progress is summarized after worker calls return; fully streamed
  per-attempt stage transitions remain future work.
- Automatic durable reconciliation of terminal-write failures without restart
  remains future work. The degraded overlay is process-local.
- This release does not claim full Kubernetes, crash-suite, or production
  deployment revalidation. CI covers compilation, frontend bundling, unit
  tests, and publication checks; real-service integration runs are local.
